(Return) Kroniki Engine

Status: early development. The engine works and there is a playable demo, but APIs, content folders and save formats are still changing between versions and there are rough edges left to smooth out. Development is active and ongoing, with the goal of covering everything expected from a game engine of this kind.

(Play the demo) (Read the guide) (Source)

What is it?

An engine for visual novels and story-driven 2D RPGs. I wanted something where writing a scene feels like writing a script, while still having a world to walk around in when a game needs one. Maps can also be turned off entirely for a pure visual novel.

  • Stack: TypeScript, React + Material UI for screens, PixiJS for the map, zustand for state, Vite, Vitest and Biome.
  • Platforms: browser, desktop (Electron, Windows and Linux) and Android (Capacitor), with keyboard, gamepad and touch input.
  • Content as code: every item, map, quest or character is a folder with a typed definition. A code generator builds a registry from the folders, so ids get autocomplete and a typo is a TypeScript error.
  • Writing: scenes can be written as plain-text .vn scripts, with an editor extension for highlighting, checks and autocomplete.
  • Art pipeline: maps are drawn in Tiled and sprites in Aseprite, both picked up by the generator.

What works so far

  • Visual novel scenes: dialogue, choices, portraits, backgrounds, effects, backlog, rewind, skip and auto mode.
  • Routes with an auto-generated flowchart, chapters and endings.
  • Maps with NPCs, doors, props, time of day and lighting, plus fast travel.
  • Gameplay systems: items, money, shops, quests, a party and turn-based battles.
  • Saves with autosave and backups, settings and translations.
  • A dev panel with hot reload, and tests for the engine.

Most of these are first versions and will keep changing as more games are built with the engine and gaps show up.

The engine comes with a guide that has step by step recipes for things like a talking NPC, a shop or a battle area.
